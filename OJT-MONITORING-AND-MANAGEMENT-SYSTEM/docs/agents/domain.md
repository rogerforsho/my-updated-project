# Domain Docs

Before exploring, read `GLOSSARY.md` at the repository root when it exists, then read relevant decisions in `docs/adr/`. If these files do not exist, proceed without creating them up front; domain-modeling skills create them when terms or decisions are resolved.

Use the glossary’s defined terms in issues, proposals, refactors, and tests. If a needed term is missing, flag it as a glossary gap. Surface conflicts with existing ADRs rather than silently overriding them.

This is a single-context repository: keep the shared glossary at the root and system decisions in `docs/adr/`.
