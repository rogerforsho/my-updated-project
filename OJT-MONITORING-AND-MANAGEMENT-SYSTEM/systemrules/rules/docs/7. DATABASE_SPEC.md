# Database Specification
## Version 2.0 Logical Baseline

This is a logical overview, not a replacement for the forward migrations in `database/migrations/` and `supabase/migrations/`. Production currently has migration drift; reconcile its actual schema before applying these changes there.

## 1. users
- `user_id` (UUID, PK, references auth.users)
- `full_name` (Text, not null)
- `email` (Text, not null, unique)
- `role` (Text, supported values: `Student` | `Coordinator` | `Supervisor` | `Admin`)
- `account_category` (generated user-facing label: OJT Student | OJT Coordinator | Supervisor | Super Admin)
- `account_status` (Text, check: `pending` | `active` | `rejected` | `inactive`)
- `created_at` (Timestamptz, not null)
- `updated_at` (Timestamptz, not null)

*Passwords are securely managed by Supabase Auth (`auth.users`) and never stored in plaintext.*

## 2. students
- `student_id` (UUID, PK)
- `user_id` (UUID, FK -> users.user_id, unique, on delete cascade)
- `student_number` (Text, not null, unique)
- `course` (Text, not null) -- ICS: BSIT, BSCS | IBE: BSBA, BSA, BSHM
- `year_level` (Int, not null, default 4) -- 4th-year students only
- `required_hours` (Int, nullable) -- Configurable per program/assignment
- `status` (Text, not null, default 'active')

## 3. coordinators
- `coordinator_id` (UUID, PK)
- `user_id` (UUID, FK -> users.user_id, unique, on delete cascade)
- `department` (legacy compatibility field; authorization uses active `staff_capability_grants` for ICS and/or IBE)

## 4. supervisors
- `supervisor_id` (UUID, PK)
- `user_id` (UUID, FK -> users.user_id, unique, on delete cascade)
- `company_id` (UUID, FK -> companies.company_id, nullable, on delete set null)
- `position` (Text, not null)

## 5. program_heads (legacy compatibility)
- `program_head_id` (UUID, PK)
- `user_id` (legacy FK -> users.user_id)
- `department_or_program` (legacy field)

Program Head is not a supported application role and must not be offered in onboarding, UI, or authorization. Keep this legacy table only while production schema and migration history are being reconciled; remove it in a separately reviewed migration after dependent policies and records are accounted for.

## 6. admins
- `admin_id` (UUID, PK)
- `user_id` (UUID, FK -> users.user_id, unique, on delete cascade)

The supported user-facing label for `Admin` is **Super Admin**.

## 7. companies
- `company_id` (UUID, PK)
- `company_name` (Text, not null)
- `address` (Text, not null)
- `contact_person` (Text, not null)
- `contact_email` (Text, not null)
- `contact_number` (Text, not null)
- `status` (Text, not null, default 'active')
- `created_at` (Timestamptz, not null)
- `updated_at` (Timestamptz, not null)

## 7a. company_branches
- `branch_id` (UUID, PK)
- `company_id` (UUID, FK -> companies.company_id, on delete cascade)
- `branch_name`, `address` (Text, not null)
- `latitude`, `longitude` (Numeric, nullable; must be a valid coordinate pair)
- `geofence_radius_meters` (Int, 50..5000)
- `geofence_enabled` (Boolean; requires coordinates)
- `is_primary` (Boolean; at most one primary branch per HTE)
- `status` (active | inactive)

## 7b. company_requests
- `request_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, on delete restrict)
- `submitted_by` (UUID, FK -> users.user_id, on delete restrict)
- Proposed HTE and branch name/address/contact fields
- `business_permit_path`, `moa_path` (nullable private storage paths; optional evidence only)
- `status` (pending | approved | rejected), reviewer, feedback, and decision timestamps
- Approved requests reference the created HTE and primary branch; decisions go through the audited review RPC

## 8. work_schedules
- `schedule_id` (UUID, PK)
- `company_id` (UUID, FK -> companies.company_id, on delete cascade)
- `day_of_week` (Int, 1=Mon .. 5=Fri)
- `time_in_start` (Time, not null)
- `time_in_cutoff` (Time, not null) -- Late status cutoff
- `time_out` (Time, not null)
- `created_at` (Timestamptz, not null)

## 9. student_assignments
- `assignment_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, on delete cascade)
- `company_id` (UUID, FK -> companies.company_id, on delete restrict)
- `branch_id` (UUID, required, references a branch belonging to the same company)
- `supervisor_id` (UUID, FK -> supervisors.supervisor_id, on delete restrict)
- `start_date` (Date, not null)
- `end_date` (Date, nullable)
- `assignment_status` (Text, not null, default 'active') -- active | completed | cancelled
- `created_at` (Timestamptz, not null)

## 10. attendance
- `attendance_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, on delete cascade)
- `assignment_id` (UUID, FK -> student_assignments.assignment_id, on delete cascade)
- `attendance_date` (Date, not null)
- `time_in` (Timestamptz, not null)
- `time_out` (Timestamptz, nullable)
- `time_in_received_at` / `time_out_received_at` (Timestamptz, nullable) -- server receipt times; distinct from device-captured event times
- `time_in_selfie_path` (Text, not null) -- Private Supabase storage path
- `time_out_selfie_path` (Text, nullable)
- `verification_status` (Text, not null, default 'pending') -- pending | verified | rejected
  - A Supervisor "Disputed" decision is stored as 'rejected', the same value a Coordinator exception rejection uses; the audit log (`ATTENDANCE_EXCEPTION_REJECTED`) tells them apart.
- `late_status` (Text, not null, default 'unknown') -- on_time | late | unknown
- `created_at` (Timestamptz, not null)
- `updated_at` (Timestamptz, not null)

## 11. reports & pre-deployment requirements
- `report_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, on delete cascade)
- `report_type` (Text, not null) -- Pre-OJT Orientation Certificate | Endorsement Letter | Daily Journal | Weekly Progress | Accomplishment Report | Incident Report
- `file_path` (Text, not null) -- Private storage path
- `submission_date` (Timestamptz, not null, default now())
- `status` (Text, not null, default 'submitted') -- submitted | reviewed | approved | rejected
- `remarks` (Text, nullable)
- `created_at` (Timestamptz, not null)
- `updated_at` (Timestamptz, not null)

## 12. evaluations
- `evaluation_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, on delete cascade)
- `supervisor_id` (UUID, FK -> supervisors.supervisor_id, on delete restrict)
- `performance_score` (Numeric, nullable)
- `feedback` (Text, not null)
- `evaluation_date` (Date, not null)
- `created_at` (Timestamptz, not null)

Supervisor evaluations are immutable after submission. A correction must be recorded as an evaluation appeal decision; the effective score may change while the original score and feedback remain available.

## 12b. OJT final grades and certificates
- `ojt_final_grades` stores one Coordinator-recorded grade per student (`final_grade` Numeric(3,2), 1.00–5.00; `recorded_by_user_id`; `recorded_at`). Students can read their own grade; Coordinators can read and change grades in their department until finalization.
- Grades from 1.00 through 3.00 are passing. Grades above 3.00 remain recorded but cannot finalize OJT or issue a certificate.
- `certificate_id` (UUID, PK), `student_id` (unique FK -> students.student_id), and `verification_code` (unique public lookup token)
- `hours_rendered`, `host_company_name`, `academic_year`, `status`, and `issued_at` describe the issued completion credential.
- `finalized_at` (Timestamptz) marks completion. The database requires a passing grade before certificate insertion and locks attendance, reports, evaluations, appeals, progress, schedules, assignments, and the grade after finalization. Certificate revocation does not reopen the academic record.
- Existing certificates are retained; migrations do not infer a final grade from Supervisor percentages. Public certificate verification does not disclose the grade.

## 12a. evaluation_appeals
- `appeal_id` (UUID, PK)
- `evaluation_id` (UUID, FK -> evaluations.evaluation_id, on delete restrict)
- `student_id` / `submitted_by` (FKs to the student and their user account)
- `appeal_reason` (Text, required, 20–3,000 characters)
- `supporting_details` (Text, nullable)
- `status` (Text: pending | upheld | adjusted)
- `decision_reason`, `resolved_score`, `decided_by`, `decided_at` (nullable until the assigned OJT Coordinator decides)
- At most one pending appeal per evaluation; each decision is made once and retained.

Students can read and create appeals for their own evaluations. OJT Coordinators can read and decide appeals only for students in their active ICS/IBE department grant. Supervisors and Super Admins cannot read appeal records.

## 13. notifications
- `notification_id` (UUID, PK)
- `sender_user_id` (UUID, FK -> users.user_id, nullable)
- `receiver_user_id` (UUID, FK -> users.user_id, on delete cascade)
- `message` (Text, not null)
- `notification_date` (Timestamptz, not null, default now())
- `status` (Text, not null, default 'unread') -- unread | read
- `related_conversation_id` (UUID, nullable, FK -> chat_conversations.conversation_id, on delete cascade) -- navigation target for generic chat alerts; does not contain message text

## 14. chat_conversations
- `conversation_id` (UUID, PK)
- `coordinator_user_id` (UUID, FK -> users.user_id, on delete cascade)
- `supervisor_user_id` (UUID, FK -> users.user_id, on delete cascade)
- `coordinator_last_read_at` (Timestamptz, nullable)
- `supervisor_last_read_at` (Timestamptz, nullable)
- `created_at` (Timestamptz, not null, default now())
- Unique pair constraint on (`coordinator_user_id`, `supervisor_user_id`)

## 15. chat_messages
- `message_id` (UUID, PK)
- `conversation_id` (UUID, FK -> chat_conversations.conversation_id, on delete cascade)
- `sender_user_id` (UUID, FK -> users.user_id, on delete cascade)
- `content` (Text, not null; trimmed, non-empty, at most 4,000 characters)
- `created_at` (Timestamptz, not null, default now())
- Messages are immutable; participants cannot edit or delete them.

## 16. announcements
- `announcement_id` (UUID, PK)
- `author_user_id` (UUID, FK -> users.user_id, on delete cascade)
- `title` (Text, not null)
- `content` (Text, not null)
- `target_role` (Text, nullable) -- All | Student | Coordinator | Supervisor | Admin (user-facing label: Super Admin)
- `target_department` (Text, nullable) -- All | ICS | IBE
- `published_at` (Timestamptz, not null, default now())

## 15. internship_progress
- `progress_id` (UUID, PK)
- `student_id` (UUID, FK -> students.student_id, unique, on delete cascade)
- `completed_hours` (Numeric, not null, default 0)
- `remaining_hours` (Numeric, not null, default 0)
- `progress_status` (Text, not null, default 'not_started') -- not_started | in_progress | completed
- `updated_at` (Timestamptz, not null)

## Core Relationships & Constraints
1. Every table has Row Level Security (RLS) enabled.
2. Completed and finalized internship records are immutable / read-only.
3. Supervisor access is strictly constrained by active `student_assignments`.
4. Only verified attendance entries contribute to `completed_hours`.
5. Chat rows are visible only to their Coordinator and Supervisor participants. Sending requires both accounts to be active and an active department-linked placement; old conversations remain readable after eligibility ends.
6. Participants may update only their own conversation read marker. Related chat notifications contain no message preview and are visible only to their receiver.
