# Product Requirements Document (PRD)
## Version 1.0

## Product Overview
The **Cross-Platform On-the-Job Training (OJT) Monitoring and Management System** is a centralized, role-based platform designed to support the management, monitoring, and documentation of internship activities for **Colegio de Montalban**, specifically for fourth-year students under the **Institute of Computing Studies (ICS)** and **Institute of Business and Entrepreneurship (IBE)**.

The system replaces fragmented manual processes involving physical documents, paper logbooks/DTRs, spreadsheets, and scattered communication with a unified **responsive web application** and **mobile application** sharing a single centralized Supabase backend.

## Goals
- Centralize OJT records across web and mobile platforms.
- Support online and offline mobile attendance capture with selfie evidence and explicit human verification.
- Automatically compute and track rendered and remaining internship hours.
- Provide digital submission for OJT reports, placement forms, and pre-deployment requirements.
- Support supervisor performance evaluations and trainee feedback.
- Deliver centralized notifications and administrative announcements.
- Provide role-specific workflows for OJT Students, Supervisors, OJT Coordinators, and Super Admins.
- Maintain immutable, read-only historical records for finalized internships.

## Non-Goals & Scope Limitations
- Offline functionality is excluded for web and reporting modules. Mobile attendance events may queue locally and sync whenever connectivity returns; device event time and server receipt time are stored separately, and every synced event remains pending until reviewed by a Supervisor.
- Automated facial recognition (biometric identity matching is excluded; selfie verification uses on-device live face presence detection and manual supervisor inspection).
- A separate native desktop client; desktop access uses the Electron web-portal wrapper.
- Job application or recruitment/hiring systems.
- Memorandum of Agreement (MOA) legal transactions.
- Payroll and general HR management systems.
- Other academic years (1st to 3rd-year students) or other educational institutions.
- External or unapproved private chat and messaging platforms. The approved in-app Coordinator–Supervisor conversation feature is included in this system.

## Target User Roles & Capabilities

### 1. OJT Student (fourth-year ICS / IBE)
- Uses the mobile app only, self-registers, verifies email, and waits for OJT Coordinator approval.
- Submits the two pre-OJT gateway documents: **Pre-OJT Orientation Certificate** and **Endorsement Letter**. Registration ID front/back images are identity evidence, not additional gateway requirements.
- Proposes a practicum work schedule, records attendance with selfie/GPS evidence, views credited hours, and submits accomplishment reports and incidents.
- Requests a new HTE when needed; the Coordinator verifies and finalizes the HTE, branch, and Supervisor.
- Receives notifications and school announcements.

### 2. Supervisor
- Uses web or desktop access and sees assigned trainees only.
- Reviews attendance evidence and approves or returns assigned daily accomplishment reports with feedback.
- Completes midterm and final performance evaluations.
- Communicates with eligible OJT Coordinators through the existing private pair conversation.

### 3. OJT Coordinator
- Uses web or desktop access with an explicit ICS and/or IBE grant.
- Reviews student email verification and registration, the two gateway documents, HTE requests/evidence, placements, exceptions, and academic progress.
- Reviews attendance exceptions and incidents within scope, oversees requirements, and assigns the final OJT grade.
- Communicates with eligible Supervisors through the existing private pair conversation.

### 4. Super Admin
- Uses web or desktop access with MFA.
- Manages account access and system configuration, and reviews security audit metadata.
- Has no routine access to academic records, student files, attendance, or chat content.

### 5. IT Experts / Evaluators
- Evaluates technical quality using selected criteria from **ISO/IEC 25010:2023** (Functional Suitability, Performance Efficiency, Usability, Security).

## Core Functional Areas
1. Authentication and Role Management (with Coordinator approval lifecycle)
2. Student Profile, Pre-Deployment Gateway (Pre-OJT Orientation Certificate and Endorsement Letter), and Practicum Work Schedule Commitment
3. Attendance Logging (Time In / Time Out with on-device face presence validation and point-in-time GPS coordinate capture)
4. Dual Verification (Selfie visual verification with face presence detection + GPS location metadata review by Supervisor with smart compliance triage)
5. Automatic Rendered-Hour Computation
6. Digital Report & Requirement Submission
7. Document Verification & Approval Tracking
8. OJT Progress Monitoring
9. Performance Evaluation Management
10. Notifications and Announcements
11. Coordinator–Supervisor Chat (web only; text messages up to 4,000 characters; live updates; unread status; no edit/delete or seen receipts)
12. Centralized OJT Records & Finalization (Read-Only upon completion)
13. Administrative & Departmental Reports
14. Read-only What-if Analysis for projected attendance pace and completion dates

### Coordinator–Supervisor Chat Scope
- Only active OJT Coordinator and Supervisor accounts may use chat. Students and Super Admins have no chat access.
- A pair is eligible when the Coordinator’s department matches the course department of at least one of the Supervisor’s active student placements. Any active Coordinator in that department is eligible.
- There is one conversation per Coordinator–Supervisor pair. Either participant may start it by sending the first message.
- If no eligible active placement remains, the existing conversation is retained as read-only history. Messaging resumes if the pair becomes eligible again.
- Opening a conversation marks its incoming messages read. The interface displays unread counts, without sender-facing read receipts.
- Each new chat message creates a generic system notification that links to the conversation and does not reveal message content. Notifications are shown in the shared Coordinator/Supervisor inbox.
- Messages are permanent, plain text, and limited to 4,000 characters. The feature is online-only and web-only in v1.
- Existing account deletion cascades apply to chat records and related notifications.

## Evaluation Standard (ISO/IEC 25010:2023)
The system undergoes evaluation on:
- **Functional Suitability:** Completeness, correctness, and appropriateness of OJT workflows.
- **Performance Efficiency:** Response times, database queries, resource utilization.
- **Usability:** Interface clarity, learnability, operability, accessibility.
- **Security:** Authentication, role-based access control, object-level protection, and signed file access.  
*(Note: Wording must strictly state that "security-related features were evaluated" rather than claiming unconditional certification.)*

## Success Criteria (Version 1.0)
1. 100% centralized data synchronization between Web (Next.js) and Mobile (React Native Expo).
2. Students can log attendance with selfie evidence and point-in-time GPS geotagging, viewing calculated hours accurately.
3. Coordinators can approve registrations, assign companies/supervisors, and track completion.
4. Supervisors can verify assigned trainees' attendance and submit performance evaluations.
5. All security checks, role-based access controls, and signed URL file protections function properly.
