# UI Requirements and Screen Inventory

Use a clear, professional green/teal visual system. Do not create filler screens. OJT Students use the mobile app only; Supervisors, OJT Coordinators, and Super Admins use web or desktop.

## Authentication
- Sign in and role-appropriate access errors.
- Student registration, email verification, and pending Coordinator review.
- One-time account setup and password recovery links. Students complete recovery in mobile.
- Super Admin MFA enrollment/challenge before administrative data loads.

## OJT Student — mobile
- Home: credited/remaining hours, attendance and submission states, and notifications.
- Attendance: time in/out, selfie evidence, connectivity/sync state, and pending review state.
- Attendance history and progress.
- Pre-deployment requirements: Pre-OJT Orientation Certificate and Endorsement Letter. Identity-card evidence remains part of registration.
- Placement and assigned Supervisor details, report submissions, and notifications.

## Supervisor — web/desktop
- Assigned students and placement details.
- Attendance evidence, including device event and server receipt timestamps, for review.
- Daily accomplishment report approval/return with feedback.
- Assigned-student evaluations.

## OJT Coordinator — web/desktop
- Scoped dashboard and registration queue.
- Students, Host Training Establishments, branches, Supervisors, and placements within ICS/IBE grants.
- Gateway-document review, progress monitoring, attendance exceptions, incidents, academic completion, and final grade.
- Attendance exception decisions show the reason and audit context.

## Super Admin — web/desktop
- Account provisioning/deactivation, system configuration, and security audit metadata only.
- Require verified MFA before loading the console or executing an administrative action.
- Do not expose routine academic records, student files, attendance details, or chat content.
